# INFOMAN1 Week 5 Lab - Reflection

The main idea is that the SELECT statement, the core command of Data Query Language (DQL), only reads data from the database and never changes it. The commands DROP and ALTER belong to Data Definition Language (DDL) and permanently modify database structure, while the commands UPDATE and DELETE belong to Data Manipulation Language (DML) and modify stored data. The correct usage of each sub-language is essential for maintaining database integrity. Thus, the SELECT statement is completely safe in terms of accidental changes to the database structure or data. Hence, such statements can be executed freely while exploring a database.

In Task 4, I deliberately removed the quotation marks around the string filter. Working query: SELECT name, species, age FROM pet WHERE species = 'Cat'; Faulty query: SELECT name, species, age FROM pet WHERE species = Cat;. The faulty query produced an error: ERROR 1054 (42S22): Unknown column 'Cat' in 'where clause'. By comparing the two queries, it becomes clear why this error occurred: omitting quotation marks leads to attempting to search the column Cat instead of filtering data for the 'Cat' string. Therefore, string values in query statements need to be placed within quotation marks.
